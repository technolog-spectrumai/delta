# The toto version this host deploys — the single place delta declares it.
#
# Exact pins only, all at the same version (the toto suite releases lockstep).
# The source is the vendored subtree at vendor/toto_libs (see
# full_secession.md); these pins must equal vendor/toto_libs/VERSION.
# deploy.py rejects the build if the vendored tree, or the wheel it produces,
# is not exactly these versions.
#
# To upgrade: pull the new toto_libs delta-branch state into the subtree,
# then bump every pin here in the same commit:
#   git subtree pull --prefix=vendor/toto_libs ../toto_libs delta --squash
#   ./deploy_local.sh            (or deploy.py <config> push)
#
# delta is a small e-learning host: it needs only toto-base (core / people /
# vault / gervazy / verbena / locations / socialhub / events / quota) and
# toto-auth (sso + login strategy via toto.auth_config). It
# deliberately does not install toto-flow, toto-works, toto-media, toto-chat,
# toto-ai, toto-graph or toto-geo — no realtime, media pipeline, graph or AI.
#
# Not listed here because delta owns them outright: toto.academy, toto.quizzes,
# toto.competence, toto.palimpsest, toto.library and toto.subscriptions live in
# this repo under delta/toto/ as a namespace portion (revived from
# toto_libs limbo/ — see vendor/toto_libs/README.md "Future-host outlook").
# They need no pin — they version with delta.
toto-base==1.8
toto-auth==1.8
