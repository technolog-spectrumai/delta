# delta

**delta** is a small **maths e-learning platform** built on the **toto** platform
— a sibling host to `zenobia` (the full platform) and `faros` (the minimal Tor
server). It stands up the base toto platform plus a suite of education apps
revived from `toto_libs/limbo/` and carried here as delta's own `toto.*`
namespace portion.

It is deliberately lean: a WSGI host with **no** Neo4j/graph, AI, realtime chat,
media/ffmpeg pipeline or Celery worker. The whole learning flow is synchronous
HTTP.

The product is specified (in Polish) in [`doc/plan/wymagania.tex`](doc/plan/wymagania.tex)
— a functional spec for a maths platform: registration + email confirmation, a
**Nauka** content tree, a practice task pool, video lessons + PDF notes, per-section
progress, a profile with subscription + discount codes, and a matura module.

---

## What it does

- **Nauka** (Learn) — a course tree: *Subject → Klasa/Poziom → Dział → Lekcja*,
  built on `toto.academy` (`Course → CourseModule → Lesson`). First areas:
  *Matematyka - szkoła średnia*, *Matura - poziom podstawowy* (extendable).
- **Task pool practice** — the core learning loop (`toto.quizzes`, delta additions):
  each section is a pool of tasks (A–D **and** open-typed answers). A **correct**
  answer leaves the pool; a **wrong** one stays and the worked solution is shown
  ("spróbuj ponownie za chwilę"). Progress = *solved / total* per section; a section
  is complete when every task is solved.
- **Skills** — `toto.competence` badges unlocked by completing modules, drawn as a
  skill forest.
- **Materials** — video lessons (`Lesson.video_file` from Vault or an external
  URL) and downloadable PDF notes (`Lesson.notes_file`); reference materials via
  `toto.library`; textbook pages via `toto.palimpsest`.
- **Subscriptions & discounts** — `toto.subscriptions` (delta's lean rewrite):
  1/3/6/12-month plans each unlocking a 5/10/15/20 % loyalty discount, a per-person
  subscription with a validity date, and discount codes shown in the profile.
  Academy enrollment is subscription-gated when an `academy*` plan is active,
  otherwise open.
- Plus the base toto platform: accounts + SSO + email confirmation, encrypted
  Vault storage, admin, i18n (Polish + English), dashboard.

## How it works

delta owns six apps as a PEP-420 `toto.*` **namespace portion** under
[`delta/toto/`](delta/toto/) (no `__init__.py` there — that would shadow the
installed wheels):

| App | Role |
|---|---|
| `toto.academy` | LMS core — courses, modules, lessons, enrollment, certificates, cohorts, skill forest |
| `toto.quizzes` | tasks (A–D + open), attempts, and the **practice pool** (`QuestionProgress`) |
| `toto.competence` | skill groups / badges (prereq DAG) |
| `toto.palimpsest` | page/section content (module notes / textbook) |
| `toto.library` | bibliography / reference manager |
| `toto.subscriptions` | plans, per-person subscription validity, discount codes, `gates.is_subscribed` |

These version **with this repo** and need no pin. The rest of the platform is the
installed **toto suite**: delta pins only `toto-base` and `toto-auth` in
[`requirements.toto.txt`](requirements.toto.txt) (no flow/works/media/graph/ai).

### The stack

| Layer | Tech |
|---|---|
| Language / framework | Python 3.11 · Django 4.2 |
| Web server | gunicorn (WSGI) + whitenoise |
| Database | PostgreSQL (+ PostGIS when `BUILD_GEO=1`) · SQLite/SpatiaLite in dev |
| Cache | Redis |
| Reverse proxy | nginx (TLS, static/media) |
| Packaging | Docker + docker compose, generated by `deploy.py` from a YAML profile |

`BUILD_GEO` is the one feature toggle delta reads: on by default (GIS via
`toto.locations`); set `0` to drop the whole GDAL/GEOS/PostGIS stack (locations
loads geometry-less). The local profile ships `BUILD_GEO=0` for a lean image.

## Usage

### Local development

```bash
python3 -m venv venv && . venv/bin/activate
pip install -r requirements.txt
python delta/manage.py migrate                # toto resolves from vendor/toto_libs
python delta/manage.py runserver
```

Getting toto onto the path, in order of preference:

1. **Automatic (default):** the vendored subtree at `vendor/toto_libs` —
   manage.py and deploy.py put its packages on sys.path when `TOTO_SRC` is
   unset (see `full_secession.md`).
2. **Another checkout:** `TOTO_SRC=/path/to/toto_suite` overrides the vendor
   tree; pointing it at a missing dir disables source resolution entirely.
3. **Editable:** `vendor/toto_libs/scripts/install_toto.sh`.
4. **Pinned wheel:** `python vendor/toto_libs/scripts/build_wheels.py --out dist`
   then `pip install --no-index --find-links dist -r requirements.toto.txt`.

`delta/manage.py` delegates to the Django project in `delta/delta/`; it honours
`TOTO_SRC` and a repo-root `.env.local`.

To prove a clean environment end to end (fresh venv, wheel built from the
vendored tree, validate/config, unit tests, check, migrate, collectstatic,
boot smoke): `scripts/clean_env_test.sh`.

To smoke-test a running stack after `./deploy_local.sh` (container health,
front-door routes, static pipeline): `scripts/smoke_test.sh`.

To test the UI **without Docker** — the early-warning harness: `scripts/ui_test.sh`
seeds a scratch sqlite DB with the deployment's own seed commands, then sweeps
every URL of the host (including the admin) with three personas (anonymous,
student, staff) via `manage.py smoke_urls`. Any 500, unexpected 404/400, or an
authenticated persona bounced to login fails the run. `--live` re-probes over
real HTTP against a throwaway runserver; extra args pass through (e.g.
`--filter academy:`). The clean-env gate runs the same sweep.

Seed the demo maths course tree + subscription plans:

```bash
FULL_INGRESS=1 python delta/manage.py ingress_academy --full
```

### Docker (local stack)

```bash
./deploy_local.sh                 # deploy.py delta_local.yaml up --smart
./deploy_local.sh logs -f         # any deploy.py command; extra args pass through
BUILD=1 ./deploy_local.sh         # force a full image rebuild
```

This brings up `web_delta` (gunicorn) + `postgres` + `redis` + `nginx` at
`https://localhost:8443` (self-signed cert), runs `init_platform` + `ingress_all`,
and seeds the demo content (`FULL_INGRESS=1`).

Inspect without deploying:

```bash
python delta/scripts/deploy.py delta/deploy/configs/delta_local.yaml validate
python delta/scripts/deploy.py delta/deploy/configs/delta_local.yaml config   # generated docker-compose.yaml
python delta/scripts/deploy.py delta/deploy/configs/delta_local.yaml env      # generated .env
```

### Remote deployment

Edit the `target:` / host fields in
[`delta/deploy/configs/delta_server.yaml`](delta/deploy/configs/delta_server.yaml),
then:

```bash
./deploy_server.sh provision      # first-time host setup
./deploy_server.sh                # rsync + start (push)
```

### toto version gate

Docker installs toto from **wheels** `deploy.py` stages into `dist/`, built from
the in-repo vendored tree at `vendor/toto_libs` (or `TOTO_SRC` / `toto_src:`). The
build is rejected unless the wheels are exactly the pinned versions, which must
equal `vendor/toto_libs/VERSION`. To upgrade:

```bash
git subtree pull --prefix=vendor/toto_libs ../toto_libs delta --squash
$EDITOR requirements.toto.txt        # bump the pin to vendor/toto_libs/VERSION
./deploy_local.sh
```

See `full_secession.md` for the full subtree workflow.
